# TRX64 spec board

The one place to look for what is open here. Every spec under `docs/NNN-*.md` has a row,
and the row's status is checked against the file by `scripts/check-spec-board.sh` — the
board and the spec cannot disagree without something going red.

**Numbers are shared with C64RE.** The registry is `../../C64ReverseEngineeringMCP/specs/README.md`
and the next free number comes from there. This board is the STATUS of TRX64's own
specs, never a second number registry — two registries is how a number gets used twice.

**Why this exists (2026-08-12).** TRX64 had no board. Status lived only in each file, so
nothing compared it to the tree, and four specs sat wrong for weeks: 791 said PROPOSED
with a shipped CLI command, a round-trip test and a parity probe behind it; 790 said
PROPOSED with both its slices done in their own header; 776 said PROPOSED for work three
other specs had delivered; and 783 said PROPOSED for something half built, where the
missing half is the enforcement everything else leans on. C64RE learned this the hard
way first — nine specs closed in one evening and not one needed building.

| 855 | [More than one SID](855-more-than-one-sid.md) | **PARTLY BUILT** | **TRX64's half is COMPLETE — D1 through D6 built and gated (`sid_multi_gate`, sixteen cases), D7 resolved without code. The row stays PARTLY BUILT because UE2's half is unstarted, and the spec is not done until both sides are.** D7 is the interesting one: `WAVES` selects the reSID model, which has been per instance since D1, and the resonance switch, digi level and 1024-entry filter curve have no reSID equivalent — so they are modelled nowhere and storing them to hand back unchanged would advertise a capability we do not have. The VSF export likewise still says one SID on purpose: VICE's layout for several is unread here, and a count this code cannot back up is the plausible-looking lie this repo keeps catching. D4 moved the audio hook from the engine to the machine as `(chip, reg, value, clk)`: per engine a host would install N hooks and re-install on every remap, and firing from the bus dispatch instead would have silently stopped tracing host pokes — a monitor write to `$D418` going quiet with nothing to show for it. Its gate caught a defect of mine in the same breath, the poke stamping `cpu6510.clk`, which is a mirror, where the bus stamps `c64_core.clk`. Slice 2 gave the machine a `SidChip` per chip and a decode table the HOST resolves and the core merely consumes, so no VICE defaults are baked in and an empty table is the pre-855 machine; `cold_reset` keeps the table because the firmware rewrites it in its own reset task. Slice 2 also uncovered a defect it did not cause: `snapshot_roundtrip_fidelity` had been red on main since TOD stopped being a countdown, because the restore recomputed a whole period instead of the captured remainder — bisected to the commit, fixed, and **both it and `resid_oracle` are now in `scripts/gate.sh`**, which is the real fix for two ungated suites rotting unseen in one day. Building D1 turned up two defects of mine in its own subject: the engine moved from BSS to the heap and reSID's constructor does not initialise the FIR ring, so engines were born full of allocator rubbish and an untouched one made sound; and the snapshot blob differed from itself because `read_state` relied on copy-assignment not carrying padding, which the standard permits but does not require. Both fixed by zeroing what the constructor does not, `offsetof` for the struct's one hole. A gate case of MINE was also too strict — byte-identity between engines, where reSID's libm table rebuild costs ±2 LSB — and was corrected to the bound the oracle already used. A U64-II decodes FOUR SID targets — two sockets, two UltiSIDs — whose addresses the firmware assigns at runtime and rewrites on every C64 reset. TRX64 has one, at `$D400`, mirrored by a `& 0x1f`. The blocker is ours and not reSID's: `resid_shim.cc:34` holds a single `SID g_sid;` and `RESID_GUARD` enforces it, so a second `Resid::new` does not run slowly, it **deadlocks**. reSID itself is an ordinary C++ class and VICE builds one per chip. So most of this spec removes a restriction we imposed. **The API was negotiated with the UE2 session and closed on both sides before either wrote a line** — handles in the shim, a decode table the host resolves and the core consumes (no VICE defaults baked in), one `Sid6581` per chip for the 6502's view, a write trace carrying `(chip, reg, value, clk)`, a host `read`+`peek` override in 850's `Option<u8>` shape, and an envelope getter. Two things are written down rather than approximated: **two reSID instances ARE sample-synchronous** (`sid.cc:982` — the cadence is content-independent; I claimed the opposite twice and was wrong), and **UltiSID's resonance switch, digi level and 1024-entry filter curve have no reSID equivalent, so TRX64 models none of them**. Open: where a SID mapped into `$DE00-$DFFF` sits against the expansion chain — neither side can show it, the U64-II top level is not in the open firmware tree, so precedence is a per-entry bool with no default. |

VICE checks alarms in every prologue and every cycle by comparing against the next pending alarm; our `process_alarms` ran the full register-access catch-up of both CIAs there instead, ~36 times per PHI2 cycle at 64 MHz. Measured, alternating A/B, 9/9 pairs: booted at 1 MHz 10.53× → 13.33× real time, RAM loop at 64 MHz 0.97× → 1.22× — the stock machine gains as much as turbo. ---

**HALF BUILT** / **PARTLY BUILT** = a named part is open, and the row says which.
**PROPOSED** = written down, nothing built.

There is no "in progress". Nothing here is being worked on right now, and a status that
claims otherwise is a lie the folder tells every visitor.

**Closed specs are not here.** Eleven moved to [`_archive/`](_archive/README.md) on
2026-08-12 — everything BUILT, RESOLVED or SUPERSEDED. A folder of finished plans reads
as a backlog, and a reader has no way to tell which is which. `_archive/README.md`
carries what was DECIDED rather than the plans themselves; that is the part that would
otherwise be re-derived from an argument nobody remembers having.

**The gate is the pre-push hook, and it is the only thing running the tests.** There is
no cloud CI (783). `hooks/pre-push` → `scripts/gate.sh`, bypassable for one push with
`GATE_SKIP=1`, which is a decision to make on purpose and not a habit.
